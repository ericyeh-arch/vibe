開始看流程 直接做檢查

02

這支影片解決的是作品分享的最後一哩路

問題

Vibe Coding 可以快速產生 HTML、CSS、JavaScript，但只在本機開啟時， 作品還不能被朋友或客戶看到。

方法

  • 先用 AI 編輯器產生一頁式靜態網站
  • 確認輸出檔案可以直接在瀏覽器開啟
  • 透過 GitHub Pages 取得公開 URL

限制

GitHub Pages 適合靜態網站，不適合需要後端資料庫的動態網站。

03

完整流程可以拆成四個可檢查的階段

04

提示詞要同時約束語言、題材與部署形式

影片中的示範方向

  • 製作一個精美的靜態網站
  • 主題可設定為 AI 人工智慧與 Python 歷史
  • 不管寫程式或解釋，都用繁體中文
  • 輸出可直接用瀏覽器開啟的前端檔案

建議補強

請產生純前端靜態網站，不要後端、不要資料庫。檔案結構保持簡單， 首頁命名為 index.html，手機與桌機都要能閱讀，最後列出需要上傳的檔案。

05

GitHub Pages 的前提是靜態網站

適合上架

HTML CSS JavaScript 圖片 字型 前端素材

不適合直接上架

資料庫 伺服器程式 登入系統 後端 API 動態產頁

如果 AI 產出的網站需要後端，應先改成純前端版本，或改用其他部署平台。

06

GitHub 端的設定重點是公開與分支部署

  1. 登入 github.com 並建立新的 repository
  2. Repository 設為 Public，避免 Pages 無法公開瀏覽
  3. 上傳 AI 產出的所有前端檔案
  4. Commit 後進入 Settings > Pages
  5. Source 選 Deploy from a branch，分支選 main
個人首頁 repo 名稱範例 username.github.io

07

部署成功後，要用 URL 做最後驗收

確認部署流程完成，沒有紅色錯誤。

GitHub Pages 頁面會顯示公開網址。

確認頁面可開啟，文字、圖片與互動都正常。

08

把影片方法轉成自己的工作清單

這套流程最適合用來快速展示作品原型：AI 生成、人工確認、GitHub 公開部署。

  • 先確認需求是否能做成靜態網站
  • 提示詞要求輸出可部署的前端檔案
  • 本機開啟 index.html 先驗收
  • 再上傳 GitHub 並啟用 Pages
